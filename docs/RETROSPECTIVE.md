# BiliSum 项目复盘报告

> 项目定位：DeepSeek Harness（DSH）插件 · B 站视频批量总结
> 交付版本：v1.0.0（发布于 2026-11-15），当前补丁 1.0.1
> 仓库：https://github.com/BunnyHerooo/dsh-bilisum
> 代码规模：JavaScript + Python 共约 5176 行（客户端 1707 行、Host 1198 行、Python Worker 910 行、其余为基础设施与渲染）
> 安装：DSH →「添加插件」→ 粘贴仓库地址 → 安装

---

## 一、项目概述

**BiliSum 是 DSH 的一个插件：把 B 站视频（链接或搜索结果）自动转成结构化 Markdown 总结报告。**

它解决的痛点很具体：B 站大量高价值内容（课程、访谈、长视频）只有视频形态，用户想「看完并记住要点」的成本极高；手动复制字幕、分段丢给模型、再整理成文档，是一套重复且易错的人工流程。BiliSum 把「解析链接 → 抓字幕（可选下视频）→ Agent 分段总结 → 落盘报告」整条链路固化成一次点击，并把中间产物（字幕、视频、日志）以可复用的目录结构留在本地。

## 二、架构演进

### 2.1 最初 PRD 设想的架构

PRD 的原始设定是一条**独立的 Python 流水线**：

- 命令行驱动，输入一段包含 B 站链接的文本
- 用 `bilibili-api-python`（async + aiohttp）取元数据与字幕，**禁止手写 WBI 签名**
- 可选 `yt-dlp` 下载原视频
- 由模型做 Map-Reduce 总结，输出 `B站总结_YYYYMMDD_HHMMSS.md`

它的问题是没有宿主：谁来给链接、谁来触发、结果给谁看，都需要另外补一层。

### 2.2 最终落地的架构（DSH Bundle 三段式）

最终实现为 DSH 的 Cordis bundle，拆成**三个职责边界清晰的进程/端**：

```
┌──────────────────────────────────────────────────────────────┐
│ Client（浏览器）  client.js                                   │
│  · sidebar.panellist 图标 + main 面板 + settings.section       │
│  · 双 Tab（链接 / 搜索）、多P勾选、日志、结果卡片、进度条        │
│  · 只调用 HTTP 路由 + fetch 轮询，不直接碰 Python             │
└───────────────▲───────────────────────────┬──────────────────┘
                │ fetch /bilisum/*          │ JSONL + HTTP 轮询
┌───────────────┴───────────────────────────▼──────────────────┐
│ Host（Node，lib/）                                          │
│  · apply(ctx, config)：注册 2 个 Agent 工具 + 11 条 HTTP 路由  │
│  · 凭据：ctx.credentials（SESSDATA）                          │
│  · 子进程：ctx.subprocess → Python Worker                     │
│  · 任务状态机：jobs / activeJobId / progress / retry          │
│  · 目录布局、一次性迁移、环境自愈、报告渲染                    │
└───────────────▲───────────────────────────┬──────────────────┘
                │ JSONL（stdout 逐行事件）    │ 参数
┌───────────────┴───────────────────────────▼──────────────────┐
│ Python Worker（python/bilisum_worker.py）                     │
│  · bilibili-api-python 取元数据 / CC·AI 字幕（含 WBI 内部处理） │
│  · yt-dlp + ffmpeg 下载（不转码，只 remux）                    │
│  · 串行、每条间隔 2s、失败自动重试一次                          │
└───────────────────────────────────────────────────────────────┘
```

**职责划分的关键决策**

| 端 | 只做 | 明确不做 |
|---|---|---|
| Client | 渲染、交互、调接口 | 不解析 B 站、不存 Cookie 明文、不直接跑 Python |
| Host | 编排、鉴权、落盘、任务状态、参数校验 | 不实现 B 站协议（交给 bilibili-api） |
| Worker | 网络与媒体处理 | 不决定目录名、不发通知、不关心 UI |

**通信方式**：Client ↔ Host 走 `webServer.register` 的 HTTP 路由 + 前端 `fetch` 轮询（因 bundle 不适用 `host.call`）；Host ↔ Worker 走 **JSONL**：Worker 把 `log / probe / video / failure / download-start / download-done / download-failed / summary / fatal` 逐行打到 stdout，Host 边解析边推进任务状态。这让「面板」和「Agent 工具」能复用同一套流水线。

## 三、核心功能清单（v1.0.0 / 1.0.1）

### 3.1 解析与抓取
- 从任意文本中提取 `BV号 / AV号 / b23.tv 短链`，支持分享文案、表情、多链接混合，自动去重
- 短链解析与元数据获取交给 `bilibili-api-python`，**不手写 WBI 签名**
- 链接里的 `?p=N` 会被识别并**默认只勾选该 P**；无 `?p=` 时默认 P1
- 多P/合集：先返回**真实分P标题**（含时长），勾选后再抓；每个 P 独立记录（key 形如 `BV号#p3`）

### 3.2 字幕
- CC 与 AI 字幕，自动挑选可用语言
- 转成 Markdown 落盘，Agent 读取后总结；长字幕按 offset/limit 分段读取（Map-Reduce）
- Cookie 校验与「确实没有字幕」分离：`-101` 判为登录态失效，而不是"无字幕"

### 3.3 下载
- yt-dlp + ffmpeg（venv 内 `imageio-ffmpeg` 自带，无需系统安装）
- 清晰度：4K / 1080P / 720P / 480P / 仅音频
- 编码偏好：**优先 H.264（avc1）**，避免 AV1 在部分播放器上的兼容问题；不转码，只 remux 成 mp4/m4a
- 串行下载，条间 2 秒防风控；单条失败 3 秒后自动重试一次
- **逐条状态**：绿 ✓ 成功 / 黄 ✕ 失败（悬停看原因）/ 蓝 ⋯ 重试中；失败行可单条重试或「重试全部失败项」，结果原地回写，不重跑整批

### 3.4 UI 与交互
- 侧边栏入口（order 30，与插件市场同层），主面板 / 设置页两处复用同一控制台
- **双 Tab**：`视频链接`（粘贴 → 解析）/ `搜索视频`（内置热门榜 + 关键词搜索 → 加入 → 抓取）
- 两个 Tab 共享同一组选项（提取字幕 / 下载 / 清晰度），状态互通
- 全局进度条并入「执行日志」标题行：字幕阶段 → 下载阶段 → 完成，有失败转警示色，结束后淡出
- 执行日志：默认折叠为一行，展开限高内部滚动
- 输出目录：面板内可改、可用**系统原生文件夹选择器**、可恢复默认
- 刷新插件：一键重置（日志、结果、勾选、输入框、Host 侧任务记录）
- 中英双语（locale 字典 + 本地化 meta）、图标与详情文档

### 3.5 工程与分发
- 标准 DSH bundle：`dsh.bundle.patch` + `dsh.client`，`lib/`（Host）、`client.js`（Client）、`python/`（Worker）
- **环境自愈**：首次加载检测 `~/.dsh/bilisum/venv`，缺失则后台自建（系统 Python 3.10+ → 无则下载 `uv` 兜底），无控制台窗口、不阻塞启动
- **可移植状态**：venv 与默认输出都在 `~/.dsh/bilisum`，不写包目录（安装后的包可能只读）
- 目录迁移：旧扁平 `subtitles/` `videos/` 树启动时一次性迁入新结构，幂等、写 `migration.log`
- GitHub：tag `v1.0.0` / `v1.0.1`，Release 附带 `npm pack` 的 `.tgz` 离线安装包

## 四、重大工程与 UI 迭代回顾

### 阶段 0 · 骨架（PRD → 可运行）
先落地 Host + Worker 的最小闭环：链接解析、Python 调用、字幕落盘、报告渲染。此时只有设置页入口。

### 阶段 1 · 入口形态三次调整
1. 设置页 → **侧边栏面板**（用户要求"点击即用"）
2. 面板位置：左下 → 左上（`sidebar.panellist` + `main`，order 30）
3. 最终：设置页保留一份镜像（`settings.section`），主入口在侧栏

**踩到的真问题**：面板卸载会丢失前端状态（轮询、日志、结果）。解法是把**任务状态放在 Host**，面板重新挂载时通过 `/bilisum/current` 重新"接上"正在跑或刚跑完的任务——这也成了后续所有状态设计的基线。

### 阶段 2 · 抓取正确性
- Cookie 失效被误报成"该视频没有字幕" → 增加 Host 侧 `probeCookie`（`nav` 接口）与 Worker 侧 `check_login`，把"登录态失效"和"确实无字幕"分开
- 目录命名从 `<视频名>/` 改为 `<视频名>_年月日_时间`，父级合集目录同样带时间戳
- 多P 选择：从"默认 P1 全抓"→"默认只抓第 1 P"→"默认只抓链接指向的 P"

### 阶段 3 · 下载能力（yt-dlp）
- 首个版本只抓字幕；加入下载后立刻暴露两个问题：**音频分片被当成成品**（扫描目录取最大媒体文件解决）、**长路径**（Windows 260 上限 → 合集 48 字 / 子集 56 字 + 括号配平 + 空格边界截断）
- 编码选择：实测同分辨率下 H.264 比 AV1 大但兼容性好，最终固定"分辨率优先、编码优先 H.264"

### 阶段 4 · 目录结构统一（两次重构）
1. `.transcripts` → `subtitles`，去掉隐藏目录
2. **最终形态**：一个视频/合集 = 一个顶层目录，内部固定 `subtitles/` 与 `videos/`

```
bilibili_summaries/
  B站总结_YYYYMMDD_HHMMSS.md
  bili_task.log
  <合集名或视频名_时间>/
    subtitles/<子集名_时间>.md
    videos/<子集名_时间>.mp4
```

迁移函数 `migrateLayout()`：识别旧的三种形态（散文件、单视频同名目录、合集目录），逐条搬到新结构，写 `migration.log`，幂等、失败只 WARN。

### 阶段 5 · 反馈与可靠性
- **失败可视化**：起因是一次真实事故——某批 18 集只成功 15 个，3 个网络超时被日志淹没。于是引入逐条状态徽章 + 单条重试 + 汇总行 + 自动重试
- **进度条**：先放在页面顶部 → 并入日志标题行（右侧），阶段化显示 `字幕 3/8` → `下载 7/18`
- **日志栏五次微调**：显示/隐藏 → 折叠 + 限高 → 固定高度面板（放弃）→ 只保留标题行 + 展开限高 300px + 内部滚动；标题行高度锁死避免按钮切换抖动

### 阶段 6 · 信息架构：双 Tab + 内置搜索
- 从"单页长表单"改为 `视频链接 / 搜索视频` 双 Tab，两个视图 `display:none` 互斥切换，状态不卸载
- 内置发现：`/bilisum/discover` 聚合热门榜与关键词搜索，统一字段并做 60s 缓存
- 操作栏抽象：两个 Tab 复用同一个 `actionRow`（主按钮 + 两个复选框 + 清晰度），彻底消除"搜索页没有下载选项"的问题
- Tab 样式四轮迭代：胶囊容器 → 仿 DSH 原生 → 去底色极简 → 收紧间距；搜索下拉从原生 `<select>` 换成自定义浮层（点外部关闭、Esc 关闭、选中打勾）

### 阶段 7 · 工程化与分发
- 从 `BiliSum/bundles/bilisum/` 扁平化为仓库根：`lib/` + `client.js` + `python/` + `scripts/` + `vendor/`
- 包名 `@local/dsh-bilisum` → `dsh-bilisum`（**同时修正客户端模块 id**，否则面板不注册）
- 环境从 `.bilisum-venv` 迁到 `~/.dsh/bilisum/venv`，输出目录同迁
- `setup-env.js`：幂等、依赖哈希校验、Windows/Unix 双平台、系统 Python → uv 兜底
- 首次加载自愈：`apply()` 检测 venv，缺失则后台拉起脚本（`windowsHide`，无黑窗）
- GitHub：仓库、topic、tag、Release、`.tgz` 附件、README 一句话安装

## 五、踩坑与 Bug 修复记录

### 5.1 环境与系统层

| 问题 | 根因 | 解决 |
|---|---|---|
| 沙箱内 `EPERM spawn EPERM` | 受限 shell 无法派生进程 | 改走 Host 内部路由验证；后续获得完整权限 |
| `pip` 卡死 / 超时 | `files.pythonhosted.org` 不可达 | 阿里云镜像 + `--no-cache-dir` + 临时目录放在工作区 |
| `bilibili-api` 报"未安装第三方请求库" | 缺 `aiohttp` | 显式加入依赖清单 |
| 磁盘检查让整个 Worker 崩溃 | 只读目录下 `shutil.disk_usage` 抛 `PermissionError`，且未被捕获 | 磁盘检查 try/except；建目录失败降级为**单条失败**而不是整批失败 |
| 安装时黑窗 + 极慢 | `prepare` 里跑 pip，Windows 子进程默认新建控制台 | `prepare` 改为 `--check` 只检查；所有 spawn 加 `windowsHide`；去掉 `detached` |
| 依赖哈希被换行符改写打乱 | git 工作区 CRLF 化 | 哈希前归一化 `\r\n` |

### 5.2 抓取与解析层

| 问题 | 根因 | 解决 |
|---|---|---|
| "这个视频无法抓取字幕" | SESSDATA 过期，被误判为无字幕 | 分离"登录态失效"与"无字幕"，状态栏显示 Cookie 是否有效 |
| `-412` 风控 | B 站对搜索/高频请求限流 | 下载串行 + 2s 间隔；搜索接口缓存 60s；错误透传提示稍后重试 |
| 多P 视频被当成同一条 | 仅用 bvid 作为主键 | 主键改为 `bvid#pN`，工具参数同时接受 `key` |
| `name 'multi' is not defined` | 重构时局部变量丢失 | 回归修复 |
| 报告列表吃掉了 `**` | `bulletList` 正则把 Markdown 粗体当列表前缀 | 收紧正则（`- * • 1. 1)` 之外不匹配） |

### 5.3 下载层

| 问题 | 根因 | 解决 |
|---|---|---|
| 下载"成功"其实是音频分片 | 合并前先扫描到了临时文件 | 对比目录新增项，取最大的媒体文件；清理 `.part` |
| 失败被静默吞掉 | `download-failed` 只进日志 | 逐条状态 + 重试 + 汇总行 + 自动重试一次 |
| 路径超 260 字符 | Windows MAX_PATH | 目录名截断（48/56）+ 括号配平 + 空格边界收敛 |

### 5.4 前端状态与布局

| 问题 | 根因 | 解决 |
|---|---|---|
| 切面板后任务"消失" | 组件卸载丢失前端状态 | 任务状态放 Host，`/bilisum/current` 重新接上 |
| 进度显示成黑色省略号 | 无下载记录被渲染成"忙" | 增加 `downloadRequested` 标记，区分"没要求下载"与"等待中" |
| 展开/收起日志高度跳动 | 折叠态与展开态内边距不同、长路径撑宽容器 | 锁定标题行高度；`overflow-wrap: anywhere` + `min-width: 0` |
| 合集标题挤掉「全选/反选」 | 单行 flex 换行导致错位 | 标题独占一行，操作组单独一行且不换行 |
| 点击「刷新插件」不清输入框 | 输入框是页面 state，重置只清了 Host | 重置时同步清空 Cookie 输入与链接文本框 |

### 5.5 工程与分发层

| 问题 | 根因 | 解决 |
|---|---|---|
| 重启后 `/bilisum/*` 全 404 | 插件在 `webServer` 就绪前 apply，早退跳过路由注册 | 改为 `ctx.inject(['webServer'])` 延迟注册 |
| 改名后侧边栏没有面板 | 客户端模块 id 仍是旧包名 | 同步改为 `dsh-bilisum` |
| 字幕写到工作区根目录 | `resolveOutputRoot` 改签名后，pipeline 仍按旧参数顺序调用 | 修正调用顺序；并统一传**已解析的绝对路径**，避免配置与面板覆盖分叉 |
| `.git` 目录损坏（只剩 objects/refs） | 仓库目录被外部破坏 | 重建仓库，`--force-with-lease` 推送并说明原因 |
| GitHub 安装后"和本地不一样" | `link:` 与 `github:` 是两种安装形态（实时目录 vs 固定快照） | 文档说明；本机保持 link，另一台用 tag 安装 |

## 六、未来扩展路线图（Roadmap）

### P0 · 直接影响可用性

| 项 | 说明 | 价值 |
|---|---|---|
| **取消正在运行的任务** | 当前只能等；长合集（28P）无法中途停止 | 避免误操作浪费带宽与时间 |
| **任务状态持久化** | 重启/重载后 `jobs` 清空，运行中的批次丢失 | 长任务不再"重启即失忆" |
| **风控与登录态的可操作提示** | `-412` / 过期 Cookie 目前只有文字 | 减少"看起来坏了"的困惑 |
| **下载续传 / 断点** | 网络抖动时可从断点继续 | 大文件（4K 2GB+）成功率显著提升 |
| **一键生成报告** | 目前需回对话说"总结这些" | 面板内闭环，降低使用门槛 |

### P1 · 能力扩展

| 项 | 说明 |
|---|---|
| **弹幕抓取与统计** | 弹幕本身是内容信号（高能点、争议点），可作为总结的辅助输入 |
| **字幕语言选择** | CC/AI 多语言场景下让用户指定优先语言 |
| **批量链接导入（txt/剪贴板）** | 一次性导入几十上百条，配合队列 |
| **定时/订阅抓取** | 关注某个 UP 的合集更新后自动增量抓取 |
| **代理与网络配置** | 企业网/海外网络环境下的必要项 |
| **编码与清晰度偏好持久化** | 记住用户选择，而不是每次默认 1080p |
| **长路径兜底（`\\?\` 前缀）** | 彻底绕开 260 字符限制，替代当前的截断策略 |

### P2 · 长期质量

| 项 | 说明 |
|---|---|
| **音频转写兜底（Whisper 等）** | 无字幕视频也能总结，显著扩大覆盖面 |
| **导出 PDF / HTML / 简报** | 报告从 Markdown 走向可分发的成品 |
| **测试与 CI** | `lib/links` 与 `lib/report` 的单元测试、Worker 的协议级 e2e、GitHub Actions |
| **可观测性** | 任务耗时、失败率、风控命中统计，便于长期维护 |
| **插件市场收录** | 完善 meta/详情页/预览图，争取官方索引 |

## 七、结论

BiliSum 从一个 Python 脚本式的 PRD，长成了具备**清晰三层架构、可恢复的任务状态、逐条可重试的下载、双入口（面板 + Agent 工具）、自愈环境与标准分发**的 DSH 插件。整个过程暴露出的问题集中在三类：**跨进程状态**（前端卸载、重启、参数分叉）、**B 站协议的现实约束**（Cookie、风控、WBI、路径长度）、**Windows 平台特性**（沙箱、控制台窗口、MAX_PATH）。

这三类问题都已沉淀为代码里的稳定结构：任务状态放 Host、错误分级而不是一刀切、路径与文件名统一收敛、环境与数据固定在家目录。后续扩展（P0 项）应优先补齐**任务生命周期控制**与**状态持久化**，这是当前距离"生产级"最实质的差距。
