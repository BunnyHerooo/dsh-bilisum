# BiliSum — B站视频批量总结

从一段杂乱的分享文案里提取所有 B站 视频，抓取信息与字幕，交给当前会话的模型做 Map-Reduce 总结，最后写出一个结构化 Markdown 报告。

## 它能做什么

- **侧边栏常驻入口**：左侧边栏面板列表里有 BiliSum 图标（便签下方），点击在主区域整页打开。
- **双 Tab**：顶部「视频链接 / 搜索视频」分段切换，互斥显示；搜索页内置 B站 热门榜单与关键词搜索（无需额外配置），勾选后可直接开抓。
- **全局进度条**：字幕（总 P 数）→ 下载（同 P 数）→ 完成，逐阶段显示 `已完成/总数 · 百分比`；有失败项时填充转黄；结束后保留 3 秒淡出。
- **多P/合集勾选**：检测到分P或合集时先返回真实标题列表，勾选后再只抓所选的 P；每 P 之间自动间隔 2 秒防风控。**默认只勾选链接指向的那一P**（链接带 `?p=5` 就是 P5，没有 `?p=` 就是 P1），其余 P 需要手动勾。对话里的 Agent 工具同样遵守链接里的 `?p=`。
- **字幕与下载互相独立**：两个勾选项可以任意组合——只提字幕、只下视频、或两者都做；两项都不选时按钮会直接提示。
- **链接解析**：从任意文本里提取 `BV` 号、`av` 号，并跟随 `b23.tv` / `bili2233.cn` 短链跳转解析；重复链接自动去重。
- **数据抓取**：元数据（标题、UP主、发布时间、时长）与字幕（人工 CC 优先，其次 B站 AI 字幕），并发抓取并按需重试。
- **降级处理**：单个视频无字幕、Cookie 失效、412 风控、视频下架等都会记入「解析失败列表」，不影响其他视频。
- **字幕缓存**：每个视频的完整字幕写成 `bilibili_summaries/subtitles/…/<视频名>_<时间>.md`，供模型分段读取。
- **报告生成**：按固定模板写出 `bilibili_summaries/B站总结_YYYYMMDD_HHMMSS.md`，包含核心主旨、详细观点、金句摘录，以及代码/教程类视频的核心步骤。

## 怎么用

1. **配置 Cookie（必须）**：点击左侧边栏底部（Settings 上方）的 **BiliSum** 按钮打开控制台，或进入 设置 → BiliSum；把 B站 Cookie 里的 `SESSDATA` 值粘贴并保存。B站 只允许登录用户获取字幕，没有它抓取会全部失败。凭据保存在 DSH 的凭据库中，不写入配置文件。
2. **准备 Python 环境**：插件通过内置的 Python worker 调用 `bilibili-api-python`，需要 Python 3.9+ 且已安装：

   ```bash
   pip install bilibili-api-python aiohttp
   ```

   插件会依次尝试工作目录下的 `.bilisum-venv` / `.venv`、环境变量 `BILISUM_PYTHON`，以及 PATH 上的 `python3` / `python`。
3. **选择任务并解析**：侧边栏点 **BiliSum** → 粘贴链接 → 在输入框下方勾选任务（两项独立，按需组合）：
   - `☑ 提取字幕（文本）`（默认勾选）
   - `☐ 下载原视频（清晰度：1080P ▾）`

   点「开始解析」。单集视频直接执行；检测到分P/合集时会先弹出勾选列表（真实标题 + 时长，默认只勾链接指向的那一P，带全选/反选），勾完点「开始抓取所选」。日志区实时输出进度。
4. **生成总结**：回到对话，让 Agent 总结这些视频（或点「复制指令」再粘贴到对话）。Agent 会读取缓存字幕、先分段总结再合并，并调用 `bilisum_write_report` 写出报告文件。

## 下载原视频

在输入框下方勾选「下载原视频」并选择清晰度即可。若同时勾了「提取字幕」，字幕会**先全部抓完**再开始下载——两者串行，避免同一时间两条 B站 请求流触发风控；若只勾下载，则不请求任何字幕接口。

- 引擎：`yt-dlp`（自动处理 B站 DASH 分片），合并依赖 `ffmpeg`
- 编码偏好：**优先 H.264（AVC）**，兼容性最好；但**清晰度优先于编码**——若该清晰度 B站 只提供 HEVC/AV1（4K/8K 常见），会回退到可用编码而不是降低分辨率，日志会写明实际编码
- 容器由插件决定：视频统一 `.mp4`，仅音频 `.m4a`（且优先 AAC 流）；**不重新编码**，只做无损伤封装
- 依赖检测：面板状态行会显示「下载可用 / 下载不可用」并给出缺失项与安装命令；不可用时勾选框置灰
- ffmpeg 优先取 `BILISUM_FFMPEG` 环境变量 → PATH → `imageio-ffmpeg` 自带静态构建（本机就是这种，没动系统 PATH）
- 视频落在 `bilibili_summaries/videos/`，目录结构与字幕完全一致：每个视频（或每一P）一个 `视频名_年月日_时间/` 文件夹，里面是同名文件
- 超过 3 小时的视频会先提示文件可能很大，但仍按用户的选择下载
- 失败只影响该条：日志里给出原因，其余继续

Agent 工具 `bilisum_fetch` 也支持：`download: true`、`quality: '1080p' | '4k' | '720p' | '480p' | 'audio'`。

## 输出位置

默认写到会话工作目录下的 `bilibili_summaries/`。本机在 `cordis.patch.yml` 里把输出钉到了子工作区：

```yaml
config:
  outputDir: F:/Deepseek-Harness/BiliSum/bilibili_summaries
  pythonPath: F:/Deepseek-Harness/BiliSum/.bilisum-venv/Scripts/python.exe
```

`outputDir` 可写绝对路径，也可写相对路径（相对会话工作目录）；`pythonPath` 省略时自动探测（工作目录、`BiliSum/` 子目录、`~/.bilisum-venv`、PATH 上的 `python3` / `python`）。

```
BiliSum/bilibili_summaries/
  B站总结_YYYYMMDD_HHMMSS.md            ← 报告（根目录）
  bili_task.log                          ← 抓取日志（根目录）
  migration.log                          ← 一次性结构迁移记录（仅在发生迁移时出现）
  <合集名>/                              ← 分P/合集：顶层目录取合集标题（截断 48 字）
    subtitles/<子集名_年月日_时分秒>.md
    videos/<子集名_年月日_时分秒>.mp4
  <视频名_年月日_时分秒>/                 ← 单集：同样的两层结构，目录名即视频名
    subtitles/<视频名_年月日_时分秒>.md
    videos/<视频名_年月日_时分秒>.mp4
```

单集与合集结构完全统一：**一个视频 = 一个顶层目录，里面固定 `subtitles/` 与 `videos/`**。目录名沿用 `safeFolderStem`（非法字符替换、按空格/括号收敛、合集 48 字、子集 56 字）。旧的扁平 `subtitles/` + `videos/` 树会在插件启动时自动迁移一次，逐行写入 `migration.log`，已是新结构则跳过。

文件夹与文件名使用视频**发布时间**（取不到时用抓取时间）；同名冲突自动追加 `_2`、`_3`。面板上的「打开文件夹」按钮可直接在资源管理器中打开 `bilibili_summaries`。

## 切换页面不会丢进度

抓取任务由 Host 进程持有，切换面板只会卸载前端界面。重新打开 BiliSum 时，页面会用 `/bilisum/current` 重新接上正在跑的任务（日志、进度继续刷新），任务已完成则直接显示结果与文件位置；同一时间只允许一个抓取任务，重复点击只会重新接上它。

Agent 也可以一步完成：直接在对话里说「用 bilisum 总结这些链接：…」，它会依次调用 `bilisum_fetch` 与 `bilisum_write_report`。

## 两个工具

| 工具 | 作用 |
|---|---|
| `bilisum_fetch` | 解析链接、并发抓取元数据与字幕、缓存字幕文件，返回每个视频的标题/UP主/发布时间/字幕字符数与 `transcriptPath`。 |
| `bilisum_write_report` | 把总结写成 Markdown 报告；`bvid` 之外的元数据自动用上次抓取结果补齐。 |

## 已知限制

- **字幕依赖 B站**：没有字幕（既无 CC 也无 AI）的视频无法总结，只会记录失败原因。
- **需要登录态**：`SESSDATA` 缺失或过期时，字幕接口会拒绝请求。
- **分P视频只取第一P**：报告针对视频主 cid（`pages[0]`），不逐P展开。
- **总结由会话模型完成**：插件不额外调用大模型 API，因此 Token 消耗发生在当前会话里；超长字幕会占较多上下文，建议一次处理少量长视频。
- **412 风控**：短时间大量请求可能触发 B站 风控，插件会重试两次后退避并在失败列表里说明。
- **正常关闭插件不会中断已开始的 UI 抓取任务**：任务在 Host 进程中运行，插件卸载后任务随之结束。
